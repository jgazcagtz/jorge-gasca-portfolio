# CV discovery outreach kit

This is an operator-only drafting aid. It is not rendered by the portfolio, and nothing here should be posted automatically. Re-check the current rules of every community immediately before posting. Never include Apollo customer names, account data, internal metrics, screenshots, or non-public operational details.

## Shared publishing checklist

- Lead with a useful observation, method, or lesson rather than a request for clicks.
- Use only facts already visible on `jgasca.io` or explicitly supplied for the CV.
- Describe suggested job titles as role fit, never as employment history.
- Disclose that `jgasca.io` is Jorge's portfolio when linking it.
- Read the current community rules and pinned self-promotion threads on the day of posting.
- Do not repeat the same post across communities, mass-message people, automate engagement, or ask for artificial votes.
- Remove the link if the discussion remains useful without it or if community rules prohibit portfolio links.
- Respond personally to questions and criticism; do not use generated replies.

## RevOps/GTM discussion draft

Possible title: `What I learned turning GTM goals into workflows people can actually operate`

The hard part of a GTM system is rarely adding one more tool. It is making sure account selection, data quality, routing, engagement, CRM updates, and human decisions describe the same operating process.

The review sequence I use is:

1. Define the customer or account decision the workflow must support.
2. Identify the data required before that decision can be trusted.
3. Make routing and ownership explicit.
4. Keep engagement rules understandable to the people operating them.
5. Verify what is written back to the CRM.
6. Test the complete path with realistic exceptions, not only the happy path.

This approach comes from bilingual SaaS onboarding work and from building my own CRM- and API-connected products. I documented the complete skills and public product evidence behind it here if context is useful: https://jgasca.io/cv/gtm-revops

Question for the community: which handoff creates the most hidden rework in your current GTM system?

## Product-builder / SideProject feedback draft

Possible title: `I turned six product builds into evidence-first case studies and would value feedback on the hiring story`

I have been building products across AI agents, language learning, small-business commerce, restaurant operations, and model/tool orchestration. The difficult portfolio decision was not what to show - it was how to show real ownership without making private source code, synthetic demos, or provider-dependent features look more complete than they are.

The structure I settled on for every product is:

- the customer problem;
- my actual role and actions;
- the current product stage;
- what the public evidence proves;
- what remains limited;
- the decision I would revisit next.

I also created four CV views from the same verified history rather than creating four incompatible stories. The product/implementation version is here: https://jgasca.io/cv/product-implementation

I would value direct feedback on one question: after opening the page, can you tell what I personally owned without reading every paragraph?

## n8n weekly self-promotion thread draft

Use only in the current weekly self-promotion thread if its rules still permit this format. Include a concrete workflow example or output before linking.

I build AI and GTM workflows that connect an input channel, enrichment or context, model/tool decisions, CRM or database state, and a human confirmation point.

One representative pattern is:

`Inbound signal -> validate identity/context -> enrich -> model/tool decision -> human confirmation for consequential action -> idempotent write -> delivery status and retry evidence`

I use this across n8n/Make/Zapier, REST APIs and webhooks, messaging channels, and custom TypeScript services. The important part is not the number of nodes; it is keeping the workflow tenant-bound, replay-safe, observable, and understandable when a provider fails.

I collected the complete automation stack and public product examples here: https://jgasca.io/cv/ai-automation

Example output to include before posting: a privacy-safe screenshot or text trace from a public demo showing the input, confirmation step, completed action, and delivery status.
